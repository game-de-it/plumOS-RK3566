# RK2023の初回起動

RG503で使用した共通の起動SDをRK2023へ移し、利用者が内蔵画面にBubbleが表示されることを確認した。SDの再書き込みは行っていない。

## TF1から回収した実機ログ

| 項目 | 実機結果 |
| --- | --- |
| 機種判定と起動 | 実行中のデバイスツリーのモデルは `Powkiddy RK2023`。カーネルは4.19.172、PID 1はplumOS init。RG503で使った修正版SYSTEMが選ばれ、起動後5.03秒で準備完了を記録した。 |
| 画面 | 内蔵の `DSI-1` は640×480。起動ロゴのフレームバッファも640×480 XRGB8888で、起動中に消去完了が記録された。 |
| SD2 | TF2はデバイスツリーの `mmc2`（`fe2c0000`）。`/dev/mmcblk2p1` をFAT32で読み書きマウントし、BubbleのROM・BIOS用パスに公開した。TF1のp5は `/storage/user`。起動ログはSD2のFATのdirtyフラグも記録した。 |
| Wi-Fi | Wi-Fiインターフェース、無線PHY、SDIOデバイスは検出されなかった。デバイスツリーに無線の定義はあるが、ログ上は今回の個体で無線チップの認識に至っていない。 |

## USB ADB

MacでADBサーバーを再起動し、RK2023のNW SERVICESでADBをOFF→ONにした。ケーブルをOTG端子へ移した後も、確認時の `adb devices -l` は空だった。ケーブルの都合でMacへの直結は未試験。

診断用の起動では、本体がOTGを `CDP=1`（給電とデータ）と認識し、`adbd` とFunctionFSは動作していた。UDC `fcc00000.dwc3` は `configured` だった。macOSのカーネル履歴にも、12:26:09と12:40:33にハブ経由で `2207:0006`（plumOS RK3566 ADB）を480 Mbpsで列挙し、構成を選択した記録があった。列挙の直後にはGoogle Chromeによる排他オープンと、その後にUSB転送エラー・切断が記録されていた。排他オープンと切断の因果関係は未特定。

TF1を戻して起動した際は、MacのADB 37.0.3が既定の `LIBADBUSB` で端末を検出したが、読み取りエラーで接続が終了した。macOSのUSB履歴では認識から切断まで0.62秒で、この起動の区間に排他オープンのエラーは記録されていなかった。

Mac側のADBを `ADB_USB_LEGACY=1 ADB_LIBUSB=0` で起動し、`server-status` で `NATIVE` を確認した。RK2023側のADBをOFF→ONにしてもUSBは再列挙されなかった。USBケーブルをOTG端子に挿したままBubbleの電源メニューから再起動すると、MacにADBが `device` として現れた。読み取り専用の `adb shell` を複数回実行し、モデル `Powkiddy RK2023`、`uid=0(root)`、Bubbleの準備完了、UDCの `configured`、SD2のマウントを確認した。ADBの方式切り替えとRK2023の再起動が両方入っているため、方式単独で切断が解消するかは未確認。
