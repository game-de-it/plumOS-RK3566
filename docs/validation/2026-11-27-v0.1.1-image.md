## Dockerでの生成と検証

- 前回Dockerで作成・実機確認したMaliSX2統合SYSTEMを入力に、OSとFEのバージョンを `0.1.1` に設定し、最新の第三者ライセンス一覧を入れて再パックした。実行経路196件、表示されるApps、9コンポーネントのランタイム検証を通過した。
- JELOS 20240206の再ビルド済みイメージ、起動画像、v0.1.0で検証した共通U-Boot FITを使い、`build-bubble-sd.sh` でイメージを生成した。v0.1.0と先頭16 MiBが一致し、p3は `SYSTEM` とそのMD5以外すべて一致した。p3のSYSTEMを成果物と照合した。
- `verify-bubble-sd.sh` でp5の初回作成、既存データの保持、試行SYSTEMから出荷時環境への復旧を確認した。圧縮イメージを展開してrawのSHA-256と一致することを確認した。

## RG353MでのFEアップデート

RG353Mを出荷時v0.1.0の既存TF1で起動し、SDの再書き込みなしで `START → System Settings → System Update` を選択した。差分は完成した2版のSYSTEMから抽出したランタイムの17ファイル。試験鍵で署名した差分のSHA-256は `4854dfd8fe1df5dd5b9fd054a10e1ad8d4662656bc27a42db0451ea6a9e3d719`。

- 出荷用公開鍵で試験パッケージが拒否されることを確認した。試験用公開鍵を実機に一時登録して、FEが署名を検証し、再起動することを確認した。
- ADBでFEのバージョンが `0.1.0` から `0.1.1` へ変わり、更新記録が `runtime_healthy` になったことを確認した。p5とSD2は読み書き可能で、OS本体のバージョン表示はランタイム更新の対象外のため `0.1.0`。
- 実機の公開鍵を出荷時の内容に戻し、パッケージを取り除いた後、通常再起動してもランタイムが `0.1.1` であることを確認した。FEのPSP一覧から『Ridge Racers 2』を起動し、プロセスが `libvulkan_malisx2.so` を読み込んで内蔵画面へ描画した。
- 試験鍵で署名したパッケージは実機検証専用。配布には出荷イメージの公開鍵に対応する署名鍵が必要。v0.1.1フルイメージのDocker検証結果は上記のとおり。
