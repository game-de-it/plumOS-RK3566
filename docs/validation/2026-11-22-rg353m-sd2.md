# RG353MのSD2認識とライブラリ切り替え

2026年11月22日（JST）。TF2スロットのFAT32カード（約58 GiB）は、カーネルから `/dev/mmcblk2p1` として読めた。plumOS initにはTF2をマウントする処理がなく、FEはTF1のp5だけを参照していた。

plumOS-Bubbleの `plumos-bubble-mount-sd2` を再利用し、RG353MのTF2を明示した。カードを `/run/media/sd2` にマウントし、その `roms` と `bios` を既存の `/storage/user/Roms` と `/storage/user/BIOS` へバインドする。TF1のp5には設定やセーブを保存する。カードがない場合はTF1にあるROMとBIOSのディレクトリを使う。ライブラリはカードが変わったときに走査し、同じカードでの通常起動では既存の一覧を使う。[plumOS-BubbleのSD2マウント](https://github.com/game-de-it/plumOS-Bubble/commit/c3e353587ec6cfcf7c5a535e1544b9803fac8bea)

USB ADBでの読み取り専用の試験では18システム・774件を取り込んだ。Dockerで検証したinitペイロードとマウントスクリプトを実機へADBで配備した。再起動後はTF2が自動で読み書き可能にマウントされ、初回の走査は1.867秒で774件を登録した。TF1のp5、FEの描画準備、ADBも確認した。

2回目の通常再起動では、電源処理でTF2を読み取り専用に切り替えてアンマウントできた。次の起動でTF2を再マウントし、同じ一覧を再走査せずに使用した。FEとADBの準備はカーネル起動から6.04秒。旧initは実機の `/storage/plumos-rk3566/init/init.pre-sd2-backup` に保存した。今回の自動マウントは起動時に行う。
