# RG353Mでの0.2.1ランタイム更新確認

2026年11月27日（JST）。正式版のバージョン表記に合わせ、更新アーカイブ名、署名マニフェスト、収録する `VERSION`、実機の表示がすべて `0.2.1` であることを確認した。[先行した0.2.1-qaの記録](2026-11-27-rg353m-v0.2.1-qa-update.md)

| 項目 | 確認値 |
| --- | --- |
| 更新アーカイブ | `plumos-rk3566-runtime-0.2.1.tar.gz`（592バイト） |
| SHA-256 | `08c0be39dec3ede70b58653377f37ba98999320e82e962395d6e3e3d9b068c90` |
| 署名マニフェスト | 適用元 `0.2.0`、適用先 `0.2.1`、機種ID `rk3566`、アーキテクチャ `aarch64` |
| 同梱Ed25519公開鍵のSHA-256 | `ffd8ac7879b6cdf9432f423c5670336709ffa802e2c63df89c891ac6ec8243a1` |

同じRG353Mで先行更新のジャーナルを確認し、その変更が `VERSION` だけであることを照合した。先行アーカイブと更新記録を退避し、出荷SYSTEMと一致するバックアップからランタイムを `0.2.0` に戻した。公開鍵と更新プログラムも出荷SYSTEMのものと一致した。

出荷版のパッケージ生成ツールと正式署名鍵で `0.2.1` のランタイム差分を作成した。差分の内容は `VERSION` のみ。Macで配布用 `.sha256` を照合し、実機の `PLUMOS/updates/` に同じ名前で置いた。標準の `START → System Settings → System Update` を実機画面で選択し、同梱公開鍵による署名検証、実機の自動再起動、`runtime_healthy` を確認した。

再起動後の内蔵画面の `INFORMATION` は `PLUMOS: 0.2.1`、実行中のランタイムは `0.2.1`、ベースOSは `0.2.0`。`/flash/SYSTEM` のSHA-256は出荷成果物の `5439d0705e84c91b5b647b012ddbccecc90de725687ca605439026c47066a053` と一致した。p5（UUID `7E1E-0DCD`）とSD2（UUID `1D0C-1A62`）は更新前後とも読み書き可能で、ROMとBIOSのSD2バインドも同じだった。
