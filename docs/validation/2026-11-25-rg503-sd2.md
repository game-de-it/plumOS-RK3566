# 共通イメージのSD2とRG503の検証

RG503でSD2が表示されないとの報告を受け、起動時のマウント条件を調べた。従来の処理はRG353M・RG353V・RGB30に限定されていた。共通SYSTEMで、起動時のDTBの `mmc2` エイリアスからTF2コントローラーを特定し、そこに接続されたSDカードの第1パーティションをBubbleのマウント処理へ渡すよう変更した。既存のFATマウントとROM・BIOSのバインドを使う。[SD2の実装](../../prototype/boot-system/manage-sd2)

JELOS 20240206の同梱DTBを `fdtget` で調べた。RG353M、RG353P、RG353V、RG503、RK2023、RGB30、RGB10 Max 3は、すべて `mmc1` が `fe2b0000`（TF1）、`mmc2` が `fe2c0000`（TF2）を指す。共通IMGの生成手順で作成したRGB30 r2用DTBも同じだった。8種類ともTF2が有効で、カード検出用の `cd-gpios` が設定されていた。

## Dockerで確認した範囲

| 試験 | 結果 |
| --- | --- |
| TF2の選択 | 通常の `/dev/mmcblk2p1` と、TF2のホストとブロック番号を変えた `/dev/mmcblk5p1` をそれぞれ選択。TF2が空ならTF1のカード、eMMC、SDIOを選ばないことを確認。 |
| 例外処理 | 候補が2件の場合はエラー。DTエイリアスや利用者領域のマウントがない場合は何もマウントしない。停止時はカード認識がなくても既存マウントの解除処理を呼ぶ。 |
| FAT32の公開 | ループデバイス上のFAT32をパッケージ内のBubbleヘルパーで読み書きマウント。UUIDの記録、`/storage/user/Roms` と `/storage/user/BIOS` の公開、書き込みの永続化、再実行、停止時のバインド解除とアンマウントを確認。 |
| 起動ロゴ | RG503用DTBは960×544。実際のロゴ描画コードを同じ解像度の模擬フレームバッファで実行し、4:3のロゴ素材が中央の725×544に収まることと、終了時に2ページとも消去することを確認。 |
| RetroArch | パッケージ内の既定値が `aspect_ratio_index = "22"`（Core Provided）であることを確認。 |

RG353Vの前回SYSTEMをベースに、SD2スクリプトを差し替えた試験用SYSTEMをDockerで生成した。SHA-256は `db8da0ca32bd24f751fe403b585a6e34cb2ae96392521bf14a6ea39b98d19e06`。SquashFSを読み直し、SD2スクリプト、Repair SD2の呼び出し先とエミュレータ・Appsの同梱を確認した。カーネルやDTBはこのSYSTEM更新に含まれない。

## RG503の実機試験

MacのUSB一覧にはハブとカードリーダーが表示された。RG503のADBデバイスは列挙されず、Mac側でADBサーバーを再起動しても接続が現れなかった。ネットワーク経由で識別できる接続先も得られなかった。試験用SYSTEMの転送、SD2の実機マウント、FEとエミュレータの起動と操作、内蔵音声、描画とFPS、Apps、スリープ復帰は保留。USB DACは別日程とする。

実機で接続できたら、960×544のDRMモードと描画範囲を取得する。4:3のゲームは左右に余白を残すこと、GB・GBAは各コア指定の比率を保つこと、PSPは960×544に収まることを画面とDRMの表示矩形で確認する。エミュレータ、内蔵PCM、Apps 9項目、ゲームやAppsの実行中の `mem` / `s2idle` 復帰はRG353Vと同じ試験基準を使う。[RG353Vの試験基準](2026-11-25-rg353v-runtime.md) · [AnbernicのRG503仕様](https://jp.anbernic.com/products/anbernic-jp-rg503)
