# RG353VのMr.Boom起動待ちと音切れの追加調査

USB ADBでRG353Vを操作した。SYSTEMは `e0ade7b9ff94efa02f7ebae7a96148e37ed543656de3f49723e40b2cacffdf71`。標準の `ondemand` で試験し、エミュレータの設定・セーブと追加の試験素材は一時領域に分けた。DRMのフレーム提示時刻、RK817のPCM状態とカーネルの `__snd_pcm_xrun`、RetroArchスレッドのCPU時間を照合した。前回の試験で描画が大きく遅れていたVirtual Jaguar、Beetle PC-FX、Beetle Saturnは今回の調査対象から外した。[前回の実機ログ](2026-11-25-rg353v-runtime.md)

## Mr.Boom

前回のログには、物理PCMの初回開始から再始動まで9.984秒または9.988秒空いた記録があった。64 msではPCMが `XRUN`、96 msでは `PREPARED` の間もフレームが進まなかった。メインスレッドの待ち先は `do_sys_poll` まで確認できていた。待っていたファイル記述子は前回のログに含まれていない。ALSA 1.2.8ではAPIから渡された待ち時間で `poll` するため、約10秒という長さだけではALSA内の待ちと特定できない。[ALSA 1.2.8のPCM待機処理](https://github.com/alsa-project/alsa-lib/blob/v1.2.8/src/pcm/pcm.c#L2666-L2758)

| 試験 | 実機結果 |
| --- | --- |
| 通常起動5回 | 前後にMicroW8、Uzebox、Mupen64Plus-Nextを起動する試行を含め、10秒停止は再現せず。 |
| 強制XRUN 2回 | PCMの開始直後に試験プロセスを180 msまたは400 ms停止。カーネルのXRUNを確認し、再開後にPCMと描画が進んだ。 |
| USB給電中のスリープ復帰後に3回 | `mem`／`s2idle` をRTCで復帰し、boot IDとUSB ADBを確認。3回とも約55〜58 fpsで描画し、PCMが進行。 |

一部の起動で短い初期XRUNは観測した。停止を入れた180 msの試験でも、再開後およそ12 msでPCMが再始動した。再現したXRUNからは約10秒の待ちを説明できず、原因は保留した。

その後、次の起動停止に備えてFDとPCM・描画を記録する診断を実機に組み込んだ。[起動停止の診断ログ](2026-11-25-rg353v-mrboom-recorder.md)

## 他シリーズの調査記録

- Bubble `96f9fa7` は低負荷NESで、ページフリップ待ちと音声生成を分けて音切れを解消した。RK3566では今回の対象にも描画スレッド分離が適用されている。Bubble `afd8801` はRetroArchメニュー復帰時のALSA再準備を修正し、RK3566の使用バイナリにも同じ処理がある。
- MF `b5bd9a8`、`7d0d134`、`b1ed6e4` はPCMポインターの計算、サスペンド復帰時の `PREPARED` からの復旧、無音による再始動を扱う。RK3566の音声ルーターにこれらの処理があることを照合した。
- Bubble `020e221` はN64の場面切替でのXRUNを記録している。V90S `e71fe2b` は描画速度とPCM再始動を分けて測定しており、今回も同様に時刻を照合した。

## コア別の切り分け

| コアと検体 | 標準起動 | 音声なし・別検体・別経路の比較 |
| --- | --- | --- |
| Uzem／Arkanoid2 | 38.10 fps、22秒の区間でPCM再始動を反復 | 音声なしでも41.83 fpsでメインスレッド97.1%。GLでも37.55 fpsとXRUN。ALSAのスレッド版はPCMが継続し、40.20 fpsだった。 |
| MicroW8／tunnel | 21.66 fps、22秒の区間でPCM再始動を反復 | 音声なしで25.99 fps、メインスレッド99.3%。controlは58.61 fps、steadyonは59.61 fpsでPCMが継続し、15秒ずつの計測で再始動なし。 |
| Mupen64Plus-Next／AeroGauge | 38秒の計測で36.64 fps、場面切替後にXRUNが集中 | 音声なしで38.95 fps。320×240でも38.76 fpsで、負荷の高い場面のXRUNは継続。ALSAのスレッド版は39.22 fpsでPCMが継続した。 |

Mupen64Plus-Nextでは `retro_run` と音声コールバックも計測した。AeroGaugeで重い場面に入ると、実行回数が約60回/秒から概ね25〜30回/秒に減り、コアが供給した音声も毎秒約44,100フレームから約18,000〜22,000フレームに減った。音声を無効にした場合も同じ場面で毎秒約28〜31回となった。毎秒55回以上の13区間で発生した4回のXRUNも、同じ区間でコア処理1回が31〜51 msに伸びていた。320×240の比較では、この13区間でXRUNは0回、重い区間では続いた。別検体のMario Kart 64でも場面をまたぐ30秒でPCM再始動を観測した。

ALSAのスレッド版は音声サンプルの不足分を無音で補うため、PCMが連続して動いたことだけでは音切れの解消を判断できない。UzemとMicroW8の重い検体では音声処理を外してもメインスレッドがほぼ飽和した。N64では場面によるコア処理の遅れと音声供給の減少を確認した。これらの負荷によるケースは音声ルーターの修正対象から外した。[RetroArch 1.22.2のALSAスレッド版](https://github.com/libretro/RetroArch/blob/v1.22.2/audio/drivers/alsathread.c#L411-L449)

低負荷の比較に使ったQuickNESはコアが約60回/秒で実行され、開始時のXRUNから約5 msでPCMが再始動した。直後の14秒の計測ではPCMが継続した。試験後は一時マウントとトレースを解除し、SDを焼き直さずにBubbleが起動していることと、音量7/20、`ondemand` を確認した。
