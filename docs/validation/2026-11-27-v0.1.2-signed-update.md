# RK3566の正式な署名鍵への移行とv0.1.2ランタイム更新

2026年11月27日（JST）。RG503を使用した。

| 配布ファイル | SHA-256 |
| --- | --- |
| `plumOS-RK3566-update-key.zip` | `57e0ced3057b2f79c676c6212012be09f30c6e776a37175c45a32c08eaf49968` |
| `plumos-bubble-runtime-0.1.2.tar.gz` | `79b9f695e8b0d60508a25bc11dfef83cac978163ad13ca0e78e0139eaff309b3` |

- RK3566専用のEd25519鍵を用意した。公開鍵のPEMファイルのSHA-256は `ffd8ac7879b6cdf9432f423c5670336709ffa802e2c63df89c891ac6ec8243a1`。新規ビルドではこの公開鍵を収録する。
- v0.1.1の出荷SYSTEMからランタイムを抽出し、正式公開鍵とランタイムのバージョンを差分としてパッケージ化した。Dockerで秘密鍵に対応する公開鍵を照合し、マニフェストの署名と配布ファイルのSHA-256を検証した。既存のメニューが認識するよう、パッケージ名は `plumos-bubble-*.tar.gz` 形式を使う。
- RG503のv0.1.1で、出荷時の公開鍵がv0.1.2の署名を拒否することを確認した。TF1のPLUMOS領域に移行ZIPを展開し、BubbleのFile Managerから `Install-Update-Key.sh` を実行した。署名の検証と更新ファイルの検出が正常終了した。
- `START → System Settings → System Update` を実行し、自動再起動後にランタイムがv0.1.2に更新された。更新は `runtime_healthy` と記録され、同じパッケージの再適用は対応元バージョンの不一致で拒否された。
- TF1から試験に使った配布ファイルを除いて通常再起動し、ランタイムv0.1.2と正式公開鍵が維持されることを確認した。OS本体はv0.1.1。p5とSD2は更新前と同じ識別子で読み書き可能としてマウントされた。
